# PKB 前端项目结构分析

## 📋 项目概览

**项目名称**: PKB Frontend (Personal Knowledge Base Frontend)  
**技术栈**: React 18 + TypeScript + Vite + Ant Design 5  
**构建工具**: Vite 5  
**状态管理**: React Context API + Zustand + React Query  
**路由**: React Router v6

## 🔄 数据流架构

### 1. 认证流程

```
用户登录
  ↓
Login页面调用 useAuth().login()
  ↓
AuthContext.login() → authService.login()
  ↓
api.post('/auth/login') → 后端API
  ↓
保存Token和用户信息到localStorage
  ↓
更新AuthContext状态
  ↓
AuthGuard检查认证状态 → 允许访问受保护路由
```

### 2. 文件上传流程

```
用户选择文件
  ↓
Home组件调用 uploadFile()
  ↓
uploadService.uploadFile() → api.post('/ingest/upload-smart')
  ↓
返回content_id和初始状态
  ↓
轮询 getProcessingStatus(content_id)
  ↓
更新UploadStatusCard显示处理进度
  ↓
处理完成 → 刷新分类和合集列表
```

### 3. 问答流程

```
用户输入问题
  ↓
AIInput组件 → qaService.askQuestion()
  ↓
api.post('/qa/ask') → 后端RAG服务
  ↓
返回答案和来源
  ↓
QAAssistant组件显示答案（打字机效果）
  ↓
保存到会话历史
```

### 4. 搜索流程

```
用户输入搜索关键词
  ↓
SearchOverlay组件
  ↓
api.get('/search', { params }) → 后端搜索API
  ↓
返回搜索结果（关键词+语义+混合）
  ↓
高亮显示匹配文本
  ↓
点击结果 → 跳转到文档详情
```

## 🎯 关键设计模式

### 1. 服务层模式
- 所有API调用封装在`services/`目录
- 统一的错误处理和类型定义
- 便于测试和维护

### 2. Context模式
- `AuthContext`管理全局认证状态
- 避免props drilling
- 提供`useAuth` Hook方便使用

### 3. 组合模式
- 组件按功能模块划分
- 可复用的UI组件（如`DocumentCard`、`CollectionCard`）
- 页面组件组合业务组件

### 4. 拦截器模式
- Axios请求/响应拦截器
- 自动添加认证头
- 统一错误处理（401自动登出）

### 5. 单例模式
- `qaService`使用单例模式
- 管理会话ID和配置

---

## 🔐 安全机制

1. **JWT Token认证**
   - Token存储在localStorage
   - 请求拦截器自动添加`Authorization`头
   - 响应拦截器检测401错误并自动登出

2. **路由守卫**
   - `AuthGuard`组件保护受保护路由
   - 未认证用户重定向到登录页

3. **用户隔离**
   - 所有API请求携带用户Token
   - 后端基于Token进行用户隔离

## 📌 注意事项

1. **API代理**: 开发环境使用Vite代理，生产环境需要配置反向代理
2. **Token安全**: Token存储在localStorage，注意XSS防护
3. **错误处理**: 401错误会自动登出，其他错误需要用户手动处理
4. **状态同步**: 使用React Query管理服务端状态，避免手动缓存
5. **类型定义**: 新增API时记得更新对应的TypeScript类型
